# SIEM Fundamentals

## Overview

Security Information and Event Management (SIEM) is a core technology used by Security Operations Center (SOC) analysts to collect, analyze, and correlate security logs from multiple systems. Instead of investigating logs separately on each device, SIEM provides a centralized platform for monitoring activity, detecting threats, and investigating security incidents.

## Log Sources

Logs generally come from two main categories:

### Host-Centric Logs
Generated by endpoints and servers such as Windows and Linux systems.

Examples:
- User authentication attempts
- File access
- Process execution
- Registry modifications
- PowerShell activity

### Network-Centric Logs
Generated by devices that monitor or control network communication.

Examples:
- SSH connections
- FTP activity
- Web traffic
- VPN connections
- Network file sharing
- Firewall and IDS/IPS events

## Challenges of Manual Log Analysis

Analyzing logs individually creates several problems:

- Large numbers of logs are generated every second.
- Logs are distributed across many devices.
- Different systems use different log formats.
- Individual events often lack enough context.
- Manual analysis makes important security events easy to miss.

SIEM solves these problems by collecting and analyzing logs from a centralized location.

## Core SIEM Features

### Centralized Log Collection
Logs from endpoints, servers, firewalls, and other devices are sent to one central platform.

### Parsing and Normalization
SIEM breaks raw logs into searchable fields and converts different log formats into a consistent structure.

### Log Correlation
Events from multiple sources are connected to identify suspicious patterns that may not appear malicious individually.

For example:

- Login from an unusual VPN IP
- Access to sensitive documents
- PowerShell execution
- Outbound network connection

When correlated, these events could indicate compromised credentials or data exfiltration.

### Real-Time Alerting
Detection rules automatically generate alerts when suspicious conditions are identified.

### Dashboards and Reporting
SIEM dashboards provide visibility into information such as:

- Failed login attempts
- Triggered detection rules
- Security alerts
- System health
- Ingested events
- Frequently accessed domains

## Common Log Sources

### Windows
Windows records activity through Event Viewer using Event IDs.

Examples include:
- Authentication events
- Process execution
- Security policy changes
- Event log modifications

### Linux
Common Linux log locations include:

```text
/var/log/auth.log
/var/log/secure
/var/log/cron
/var/log/kern
/var/log/httpd
```

### Web Servers
Apache and other web servers record incoming requests, responses, errors, IP addresses, HTTP methods, and user agents.

Common locations include:

```text
/var/log/apache
/var/log/httpd
```

## Log Ingestion Methods

SIEM platforms can receive logs through several methods:

- **Agent / Forwarder** – Software installed on endpoints that forwards logs to the SIEM.
- **Syslog** – Standard protocol used by network devices and servers to send logs.
- **Manual Upload** – Offline logs can be uploaded for analysis.
- **Port Forwarding** – Systems send logs directly to a SIEM listening on a configured port.

## Detection Rules

Detection rules monitor specific log fields and trigger alerts when predefined conditions are met.

Examples:

```text
5 failed login attempts within 10 seconds
→ Multiple Failed Login Attempts
```

```text
Multiple failed logins followed by a successful login
→ Successful Login After Multiple Failed Attempts
```

```text
Outbound traffic greater than a defined threshold
→ Possible Data Exfiltration
```

### Windows Event Log Examples

**Event ID 104 – Event Log Cleared**

```text
IF LogSource = WinEventLog
AND EventID = 104
THEN trigger "Event Log Cleared"
```

Clearing logs may indicate that an attacker is attempting to remove evidence after compromising a system.

**Event ID 4688 – Process Creation**

```text
IF LogSource = WinEventLog
AND EventID = 4688
AND NewProcessName contains "whoami"
THEN trigger "WHOAMI Command Execution Detected"
```

Commands such as `whoami` may be used by attackers during system enumeration or post-exploitation.

## Alert Investigation

When an alert is generated, SOC analysts investigate the associated events and determine whether the activity is legitimate or malicious.

Possible outcomes include:

- False positive → tune the detection rule.
- True positive → continue investigation.
- Contact the system or asset owner.
- Isolate a compromised endpoint.
- Block a malicious IP address.
- Begin incident response procedures.

## Key Takeaways

- SIEM centralizes security logs from many systems.
- Parsing and normalization make different log formats easier to analyze.
- Correlation provides context across multiple security events.
- Detection rules automatically identify suspicious behavior.
- Dashboards help SOC analysts monitor large environments efficiently.
- Analysts investigate alerts to determine whether they are true or false positives.
- SIEM plays a major role in threat detection, investigation, and incident response.
